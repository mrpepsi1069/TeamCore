# What the dashboard covers

✅ = working end-to-end (page → API → MongoDB → bot where Discord is involved). Everything below was built; the "limits" column says exactly what each page does and doesn't do.

The navigation is grouped: **Overview**, then **Club · Records · Community · Scheduling · Players · Automation · Insights · Server**, then **Preferences**. Pages that overlapped were merged into tabs, and old links still land on the right one:

* **Leagues & results** (nav entry: *Teams & games*) — Leagues, Teams, Rosters, Matches, Standings, Competitions, Divisions. `teams`, `team_members`, `matches`, `leaderboard`, `competitions` and `divisions` deep links all open the matching tab.
* **Records** — parsed Football Fusion stats, sliced by season, week and team; the old `ff` link opens it.
* **Polls** — Active and Archive tabs; the old `poll_archive` link opens Archive.
* **Scheduling** — gametimes and time-option polls (tabs) sit in one sidebar group together with events, countdowns, scheduled messages and reminders.

| Spec item | Page | Notes / limits |
|---|---|---|
| Server overview | Overview | Live counts, bot-online indicator, recent audit entries, manual "Sync with Discord" |
| Server configuration | Settings | The same keys `/setup` uses (roles, channels, timezone, activity tracking). **Results channel** is where every match is posted with its score, competition and — when there is one — the attached screenshot and Football Fusion stats: matches from the dashboard, `/match log` and the import dialog all go there (the bot needs Send Messages); leave it empty to post nothing |
| Leagues | Leagues & results → Leagues | A league is a row in the bot's own `leagues` collection (`/league`): name, abbreviation, signup link, league role. A team belongs to a league when its **League / competition** value matches the league's name or abbreviation, so teams created in Discord group correctly. Can't delete a league while teams still belong to it |
| Teams & records | Leagues & results → Teams | +Win/+Loss/+Tie, "Set…", reset and full history inline, with teams grouped under their league. **History** is a timeline: besides record changes it takes dated notes (what happened, on the day it happened), which `/record history` shows too. Notes can be edited or deleted from the same modal; record rows never change. Roster rules: one row per player per team, unique jersey numbers. Creating a team also creates the Discord role named after it (the bot needs **Manage Roles**), and the role id is stored on the team: from this page it uses the colour picked in the form, and `/record create` in Discord creates it too, in the default colour. Renaming or re-colouring the team updates that role, deleting the team removes it, and saving an older team gives it one. Also `/roster` in Discord |
| Rosters | Leagues & results → Rosters | Grouped by team: each team's name and league appear once, with its players underneath — Discord ID, position, jersey and status — instead of repeating the team on every row. Search across players, teams and positions, add or edit one player at a time, or remove a player. **New roster** builds a whole team in one go: pick the team, then enter a Discord ID, username and position per player (blank rows are ignored), up to 25 players per team — backups included. One row per player per team, unique jersey numbers. Players pick their team from the same list members do |
| Match history | Leagues & results → Matches | Pick both teams, or leave the away team empty and type the opponent's name when they aren't in the dashboard (the record update then only touches your team). Optional "update team records" adds W/L/T and is logged. **Import game stats** handles all three sports: a Football Fusion report keeps its per-player stat sheet behind **Stats** (both exports are read — the long report, or the short “27 - 25 /// {…}” one — pasted into the dialog or uploaded as a `.json` / `.txt` file), and before anything is saved it shows “Will submit your team vs the stat-sheet team” with the score, a **My team** choice when both sides are dashboard teams, and a **flip the score** option because the short export never says which score belongs to which team. while Practical Basketball and Ultimate Football take the box-score screenshot itself — pick your team, the opponent and both scores, attach the image, and it is stored with the match behind **Screenshot**. Either way the screenshot (when attached) is posted with the result in the results channel. Nothing is read out of the image. A match logged with just a score can get its stats later: **Edit** on the match opens *Stat sheet & screenshots*, where a Football Fusion export (pasted or picked as a `.json` / `.txt` file) attaches the sheet and applies the report's score, and further box-score images can be added, up to 8 per match. A short Football Fusion export (“27 - 25 /// {…}”) carries no game title, so the dialog shows **Season** and **Week** boxes for it, prefilled from the last imported game, and stores them on the match's stat sheet for the Records filters. Also `/match` in Discord |
| Records | Records | Parsed Football Fusion stats only — the other sports keep a screenshot, so no leaderboard exists for them. Every report is totalled per player and position, then sliced by **season** (`S2`), **week** (`Week 2`) and **team**, on top of the competition filter, so one week or one team's whole season can be read on its own; a week chosen without a season is read inside the latest season, so Week 2 never blends seasons; a slice with no games keeps the filters that produced it and says the slice is empty instead of quietly loosening them. Season and week are read from the report's own title line (“PFG || S2 Week 2”), not stored at import, so reports imported before these filters existed slice like new ones; a report whose title names no period only appears under *All seasons* / *All weeks*. Pick a stat to sort the leaderboard; **clicking a player** opens their game log — every stored stat sheet behind that total, newest first, with the opponent, the season and week, the score from their side and that position's stat line, using the same filters as the page so the lines add up to the total. The recent games below show their period and their stat sheets. Old `ff` links open this page |
| Standings | Leagues & results → Standings | Sort by wins / win % / fewest losses, filter by league & division |
| Competitions & divisions | Leagues & results → Competitions, Divisions | Teams pick from them. A competition can be renamed, which renames it on its divisions and teams; a division can be renamed or moved to another competition, and the teams in it move with it. Neither can be deleted while teams still use it |
| Member directory | Members | Searchable list of everyone the dashboard knows (access grants, roster rows and the last synced member list) with access level, team, position, jersey, roster status and **Cash balance** (read from the bot's `economy_accounts`, shown as `$5,000 Cash`). | **Sync members** asks the bot to publish Discord's member list; **Discord roles** are diffed and applied by the bot. Staff can view and sync, managers edit team/roster fields, only admins change access levels or roles |
| Cash economy | Members | Everyone starts with **$5,000 Cash** per server — no bank, no negative balances, exact $0 allowed. The Members page shows each balance in the same `$1,000 Cash` format the bot uses and ranks the server's top five holders in a **Cash leaderboard** above the table (sorted from the rows already loaded, so it costs no extra request and can't disagree with the Cash column). Cash moves only in Discord (`/balance`, `/pay`, `/casino`), so the dashboard can't create money, and only the bot owner can add, remove or set balances (`/cash …`, answered privately, one ledger row per change). Every change is an atomic MongoDB update guarded by the current balance, and each movement is recorded in `economy_transactions` with its own transaction id. `/daily` pays `$500` with a growing streak bonus (keyed by UTC date, so it can only pay once a day), casino results keep a **Play Again** button, and the global board's footer shows the viewer's own rank. A server owner can switch Cash off from `/setup` and admins from **Server settings** (the `economy_enabled` setting, on by default). The **Economy** page reports Cash in circulation, the last 30 days of faucet vs sink from the ledger, and each casino game's observed RTP against its configured one, with the same on/off switch. `/daily` requires a Discord account at least 7 days old and 24 hours in the server, so new accounts can't farm it |
| Statistics voice channels | Statistics Channels | Create/edit/remove; the bot creates the locked, visible voice channels. Types: members, humans, bots, boosts, one team's record, **overall team record** (every team's wins/losses/ties added up across all leagues, with win %), **championship rings** (server total, plus distinct leagues), **rings by league** (one league's rings, chosen by abbreviation or name), and custom. Templates take `{value} {name} {wins} {losses} {ties} {record} {pct} {teams} {rings} {leagues} {league} {seasons}` |
| Moderation | Moderation | Lock/unlock channels (original permission restored) + searchable log. **Kick/ban are not exposed on the web by design** (use Discord's own tools) |
| Polls | Polls (Active / Archive tabs) | Create/end/delete; voting happens on the Discord message, results and closed polls are read back here |
| Gametimes & time polls | Scheduling → Gametime, Time options | Posted by the bot to the server's **gametime channel**, exactly like `/gametime` (Can make / Can't make / Unsure buttons, optional DMs to the pinged role) and `/times` (2–6 options, one button each). Staff post gametimes, managers post time polls. The recent list covers polls created here **and** with the slash commands, each with a jump link |
| Giveaways | Giveaways | Create, end, reroll, role + account-age requirements |
| Countdowns & events | Countdowns, Events | Countdowns publish a live-ticking message; events are a calendar list with a 24 h notification |
| Member activity / growth | Member activity, Member growth | Activity tracking is opt-in per server; member growth uses hourly snapshots |
| Custom embeds / announcements | Announcements & Embeds | Full embed (author, image, thumbnail, footer, fields, colour, role ping) |
| Role panels | Role Panels | Buttons or dropdown, role limit; refuses roles with moderator/admin permissions |
| Backups | Backups | Roles/channels/permissions/basic settings. Restore: "add missing" (safe) or full (owner only, typed confirmation) |
| Suggestions | Suggestions | Approve/deny with a response. The decision is saved immediately, then the bot updates the message and DMs the author — if the bot is offline the decision still stands |
| Scheduled messages, reminders | Scheduled Messages, Reminders | Once / daily / weekly; sent by the bot; no `@everyone` pings |
| Automation workflows | Workflows | Triggers: member joins / leaves. Actions: send message, add role, DM member |
| Webhooks | Webhooks | URLs encrypted, never shown again; "Send message" posts through the webhook |
| Player profiles, tryouts, scouting, awards, hall of fame | Players section | Full CRUD. Awards share data with `/award` + `/awardcheck` |
| Verification | Verification | Posts a button message that gives a (non-privileged) role |
| Staff shifts, reports | Staff shifts, Staff reports | Records only — who worked when, and staff reports against members. Access itself is granted on **Members** |
| Appeals | Appeals | Approve/deny, optional **unban in Discord** |
| Themes, timezone | Preferences | Per-user accent colour + display timezone; server timezone in Settings |
| Data exports | Data export | JSON or zipped CSV of any collection (secrets excluded), capped at 20 000 rows per collection |
| Audit log | Audit Log | Every dashboard change |

## Deliberately not built
* **Screenshot to text (OCR).** Screenshots are kept and posted as images, not read: managers type the score and the image is the stat sheet. That keeps the deploy dependency-free and avoids wrong numbers from a misread. Football Fusion is the only sport whose report is parsed into stats.
* **Command aliases.** Discord slash commands can't have user-defined aliases; the only way is prefix/text commands, which need the privileged *Message Content* intent the bot intentionally doesn't use. Rather than ship a button that does nothing, it is left out.
* **Arbitrary automation (if-this-then-that).** Workflows are limited to the join/leave triggers and three actions above.
* **Kick/ban/timeout from the web.** Available only through Discord commands.
* **A live member list without the bot.** Discord only gives a server's member list to a bot holding the token, so **Members** shows a snapshot the bot publishes when someone presses *Sync members* (`members_sync`). The API can't refresh it on its own, and Discord role changes need the bot online. User fields elsewhere still take a Discord ID (right-click user → Copy User ID).
